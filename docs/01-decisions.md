## 노션 연동 검토

현재 DB 속성: `이름`(제목), `분류`(select), `관계`(select), `참석 가능 확인 완료`(status: 시작 전 / 진행 중 / 불참 / 참석).

- **연동 가능.** 단, 브라우저에서 노션 API를 직접 호출할 수 없으므로(토큰 노출) Vercel 서버리스 함수를 중간에 둔다. 사이트 → 함수 → 노션.
- **추가 속성 필요** (사이트가 기록): `참석 시간대`(select, 12:30–13:30 … 18:00–19:00), `인원`(number), `청첩장`(select: 실물 / 모바일), `우편번호`, `주소`, `전화번호`(각 text), `사이트 응답일시`(date).
- **이름 매칭:** 하객이 입력한 이름으로 기존 행을 찾아 갱신한다. 없거나 동명이인이면 새 행을 만들고 `분류` 비움 + 메모로 표시해 두 사람이 정리한다. 동명이인 가능성이 있으면 전화번호 뒷자리로 구분하는 방식도 가능.
- **슬롯 잔여 인원**은 노션에서 `참석 시간대`별 `인원` 합계를 읽어 계산한다. 노션 API 지연은 0.5–1초 수준이라 폼 진입 시 한 번 읽어 두면 된다.
- **필요한 것:** 노션 통합(integration) 토큰 발급 후 이 DB에 연결. 발급 방법은 안내 예정. 토큰은 Vercel 환경변수에만 둔다.

## 문자/카톡 발송 검토

- **카카오톡 알림톡·친구톡은 사업자 채널이 필요**해 개인 결혼식 용도로는 사실상 불가.
- **문자(SMS/LMS)는 가능.** 솔라피 등 개인 가입 가능한 서비스, 발신번호 본인인증 필요, 건당 약 20–50원. 70명 기준 비용은 수천 원.
- 이미지 티켓을 문자로 보내면 MMS(약 100–200원/건)이고 화질이 떨어진다. **권장: 문자에는 개인 티켓 링크만 보내고, 링크를 열면 이름·시간대가 들어간 티켓이 표시되고 이미지로 저장할 수 있게 한다.**
- 자동 발송은 신청 즉시 서버리스 함수가 문자를 보내는 구조. 실패 시 재발송 수단이 필요하므로, 노션에 `티켓 링크` 속성도 함께 기록해 두 사람이 수동으로 다시 보낼 수 있게 한다.
- 대안: 자동 발송 없이 사이트에서 즉시 티켓 표시 + 두 사람이 노션의 링크를 카톡으로 직접 전송. 70명이면 수동도 현실적이고 외부 서비스 계약이 없다.
